<analysis>**original_problem_statement:**
The user wants to build a valet parking platform called SwiftValet.

**PRODUCT REQUIREMENTS:**
- **User Roles:**
    - **Customer:** Interacts via WhatsApp, no app needed.
    - **Valet Driver:** Uses a React PWA for intake, scanning, logging, and GPS pinning. Logins via OTP.
    - **Admin:** Manages valet drivers (add/delete), tracks tips, and views all car statuses for their specific client (e.g., a restaurant). Logins via OTP.
    - **Super Admin:** A top-level role that can add/manage Admins for different clients and view platform-wide analytics. Logins via email/password.
- **Functional Requirements:**
    - **Phase A: Intake & Parking**
        - Quick Intake: Valet enters Phone Number, License Plate, and a physical Tag Number.
        - The intake is a 2-step process: 1. Car Handoff (Phone, Plate), 2. Parking Location (GPS, Landmark, Tag Number).
        - GPS should be optional.
        - Auto-Notification: A WhatsApp message is sent to the customer with parking details.
    - **Phase B: Retrieval & Claiming**
        - Request: Customer replies RETR to the WhatsApp message to create an Open Ticket.
        - Claim: A push notification is sent to all active valets. The first to claim gets the ticket.
    - **Phase C: The Ghosting Protocol**
        - 5-Minute Rule: A timer starts when the car arrives.
        - Return to Park: If the customer doesn't show up, the valet can return the car to a parking spot.
    - **Phase D: Handover & Gratuity**
        - Handover: Valet marks handover as complete.
        - Tipping: (Deferred for now).
    - **Admin & Super Admin Features:**
        - Admins can add their name and their client's name (e.g., restaurant name) in a profile section.
        - When adding valets, Admins must collect a driver's license photo and number.
        - Super Admins have a dashboard to view platform analytics.
        - Valets and Admins are created using their phone number, without a password.
