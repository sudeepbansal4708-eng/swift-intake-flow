<analysis>**original_problem_statement:**
The user wants to build a valet parking platform called SwiftValet.

**PRODUCT REQUIREMENTS:**
- **User Roles:**
    - **Customer:** Interacts via WhatsApp, no app needed.
    - **Valet Driver:** Uses a React PWA for intake, scanning, logging, and GPS pinning.
    - **Admin:** Manages valet drivers (add/delete), tracks tips, and views all car statuses for their specific client (e.g., a restaurant).
    - **Super Admin:** A top-level role that can add/manage Admins for different clients and view platform-wide analytics.
- **Functional Requirements:**
    - **Phase A: Intake & Parking**
        - Quick Intake: Valet enters Phone Number, License Plate, and a physical Tag Number.
        - The intake is a 2-step process: 1. Car Handoff (Phone, Plate), 2. Parking Location (GPS, Landmark, Tag Number).
        - GPS should be optional to allow testing in preview environments.
        - Auto-Notification: A WhatsApp message is sent to the customer with parking details, including the client's name (e.g., Welcome from The Grand Restaurant!) and the tag number.
    - **Phase B: Retrieval & Claiming**
        - Request: Customer replies RETR to the WhatsApp message to create an Open Ticket.
        - Claim: A push notification is sent to all active valets. The first to claim gets the ticket.
        - Streamlined Claiming: Claiming a ticket should immediately open the ticket details view.
        - Simplified Status: Valet marks the car as ARRIVED at the curb (combining previous En Route and Arrived steps).
    - **Phase C: The Ghosting Protocol**
        - 5-Minute Rule: A timer starts when the car arrives.
        - Return to Park: If the customer doesn't show up, the valet can return the car to a parking spot, with an option to update the location if a better spot is available.
    - **Phase D: Handover & Gratuity**
        - Handover: Valet marks handover as complete.
        - Tipping: (Deferred for now).
    - **Admin & Super Admin Features:**
        - Admins can add their name and their client's name (e.g., restaurant name) in a profile section.
        - When adding valets, Admins must collect a driver's license photo and number for verification.
        - Super Admins have a dashboard to view total clients, currently parked cars, and cumulative tips for the day.

**User's preferred language**: English

**what currently exists?**
The application is a full-stack valet platform with a React frontend and FastAPI backend. It supports four user roles: Valet, Admin, Super Admin, and the customer (via WhatsApp).

Key implemented features include:
- JWT-based authentication for all app roles.
- A multi-step vehicle intake form (phone, plate, optional GPS, landmark, tag number).
- Twilio integration for sending WhatsApp notifications upon parking.
- A retrieval ticket system initiated by the customer replying RETR (the webhook code is ready but requires user configuration in Twilio).
- Role-based dashboards for Valets, Admins (driver management, license viewing), and Super Admins (client management, analytics).
- A simplified retrieval workflow and an option for valets to Return to Park with a location update.
